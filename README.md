# TwoLink VPN

Инфраструктура для продажи прокси/VPN-доступа (VLESS+Reality, Shadowsocks в
резерве, WireGuard опционально) через Telegram-бота.

## Стек

- **Xray-core** — VLESS+Reality (основной протокол) + Shadowsocks (резерв)
- **WireGuard** — опционально, отдельный compose-профиль
- **FastAPI** — управление пользователями/нодами, выдача subscription-ссылок
- **PostgreSQL** — пользователи, подписки, лимиты трафика, ноды
- **aiogram** — Telegram-бот
- **Docker Compose** — оркестрация
- **Prometheus + Grafana** — мониторинг (опциональный профиль)

## Окружения

| | Локальная разработка | Прод |
|---|---|---|
| Хост | Ubuntu VM (VMware Workstation) | Ubuntu VPS (2 vCPU / 2GB RAM / 60GB SSD) |
| Конфигурация | `docker-compose.yml` | `docker-compose.yml` + `docker-compose.prod.yml` |
| Отличия | через `.env` | через `.env` |

Перенос с VM на VPS не требует изменений кода — только `.env` и запуск с
`docker-compose.prod.yml`.

## Быстрый старт (локальная разработка)

```bash
cp .env.example .env
# заполнить .env реальными значениями для локальной разработки
cd docker
docker compose up -d
```

## Безопасность — обязательные принципы

- Секреты только в `.env` (не в git, не в коде). В репозиторий коммитится
  только `.env.example` с плейсхолдерами.
- Все контейнеры работают от непривилегированного пользователя.
- Наружу публикуются только необходимые порты (Xray, вебхук бота при
  необходимости). PostgreSQL и внутренний API — только во внутренней
  docker-сети.
- Reality-ключи генерируются локально (`xray x25519`), никогда не
  хардкодятся и не коммитятся.
- Внутренний API-ключ разделяет бота и бэкенд; бэкенд не публикуется в
  интернет напрямую в проде.
- Токены подписок — криптографически случайные (`secrets.token_urlsafe`),
  не последовательные ID.

### Рекомендации по SSH/ОС (вне Docker)

При настройке хоста (VM/VPS) отдельно от Docker-конфигурации:

- сменить порт SSH с 22 на нестандартный;
- отключить вход по паролю (только по ключу);
- отключить root-логин по SSH;
- настроить `fail2ban`;
- настроить `ufw` (разрешить только SSH, HTTP/HTTPS, Xray-порт).

## Масштабируемость

- Таблица пользователей в PostgreSQL с самого начала содержит `node_id` —
  привязку к конкретному серверу, даже если сейчас нода одна.
- Бэкенд не хардкодит обращение к Xray на `localhost` — адрес ноды берётся
  из конфигурации/БД, что позволяет управлять несколькими серверами из
  одного бэкенда.
- Subscription-эндпоинт проектируется под список серверов, а не под один
  захардкоженный.
